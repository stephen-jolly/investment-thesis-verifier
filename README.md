# 投资命题多证据验证台（Investment Thesis Multi-Evidence Verifier）

> 把一个模糊的「投资命题」自动拆解为可验证子问题，调用真实金融数据形成**支持 / 反对 / 无法验证**的证据链，处理证据冲突，给出**可追溯结论**，并明确「哪些信息变化会翻转当前结论」。

本项目为同花顺 2027 届校招「AI 产品经理（AIME 金融智能 Agent 方向）」测评作品（选题：投资命题与多证据验证）。

---

## 一、它解决什么问题

投资者经常形成需要验证的判断，例如：

- 「贵州茅台 2023 年盈利增长主要来自主营业务」
- 「宁德时代估值回落但基本面没有恶化」
- 「比亚迪近三年盈利能力持续提升」

这些命题往往**模糊、复合、想当然**。人工验证需要：拆问题 → 查报表 → 对数据 → 找反例 → 下结论，耗时且容易只看到支持自己观点的证据（确认偏误）。

本产品把这条研究流程自动化、结构化、可追溯，并**强制同时呈现支持与反对证据**。

---

## 二、目标用户

- **个人投资者 / 投研新手**：需要一套严谨的命题验证框架，避免拍脑袋；
- **专业研究员 / 分析师**：作为研究初稿与证据整理工具，快速形成可追溯的研究底稿；
- **投研团队**：用于研究结论的交叉复核与证伪。

---

## 三、核心链路（产品主流程）

```
输入投资命题
   │
   ▼
① 命题拆解 ── 识别标的、核心主张、时间范围，拆成 3-5 个可验证子问题
   │            （命题模糊时提出澄清问题）
   ▼
② 标的确认 ── 解析为完整 thscode（如 600519.SH），缺失时用检索接口兜底
   │
   ▼
③ 分组取证 ── 按数据工具分组，扶摇与 iFinD 多源【并行】取数（含限流退避重试）
   │
   ▼
④ 证据分类 ── 对每个子问题输出 supporting / opposing / unverifiable 证据
   │            （标注证据强度、事实/推断、字段、来源、时点）
   ▼
⑤ 综合结论 ── 总体判断 + 置信度 + 证据冲突 + 关键翻转条件 + 后续研究动作
   │
   ▼
⑥ 继续追问 / 比较 / 保存为研究任务
```

**总体判断取值**：`confirmed`（成立）/ `partially_confirmed`（部分成立）/ `refuted`（不成立）/ `inconclusive`（无法判断）。

## 四、产品功能（简洁对话式 Agent）

产品采用「**对话外壳 + 结论先行的 Markdown 报告**」：像聊天助手一样自然交互，回答以干净、轻量结构化的文字呈现（标题、要点、来源链接），不使用花哨的彩色卡片；内部仍保留严谨的多证据验证 Agent 内核。

| 模块 | 说明 |
|---|---|
| 会话界面 | 左侧会话历史 / 新建对话，中间消息流，底部输入框；空状态可一键使用示例命题 |
| 轻量阶段提示 | 验证时以一行灰色小字提示「理解命题 → 调取数据 → 综合结论」进度，完成后自动收起，不长期占屏 |
| 结论 | 开头第一句给出判断（成立 / 部分成立 / 不成立 / 无法判断）与置信度，1–2 句话讲核心理由，用户只看这一段就知道答案 |
| 关键依据 | 最多 3 条要点，每条包含关键数字并在句末标注数据来源 |
| 子问题验证 | 每个子问题一行「问题：结论」，不展开冗长推理 |
| 关键翻转条件 | 2–3 条，说明哪些指标达到什么阈值会改变结论 |
| 资料来源 | 列出 iFinD **具体公告标题与发布日期**，并附巨潮资讯网年报原文链接，可点击溯源（不向用户倾倒原始 JSON） |
| 多轮追问 | 基于已有结论继续提问，回答逐字真流式输出、结合上下文、区分事实与推断 |
| 范围边界 | 与投资研究无关的问题（如问日期、闲聊、写代码）礼貌说明服务范围并引导，不强行作答 |
| 会话历史回放 | 会话保存在侧边栏，刷新后可点击回放完整 Markdown 报告（服务内存期内） |

## 五、AI 的角色（人机分工）

大模型（豆包 Doubao）在产品中承担**三个分析角色**，但**不直接接触、也不允许编造原始数据**：

1. **拆解分析师（Decomposer）**：把命题结构化、拆成可验证子问题、选择数据工具、给出验证逻辑；
2. **证据分类员（Evidence Classifier）**：基于系统取回的真实数据，组织支持/反对/无法验证证据，区分事实与推断；
3. **研究负责人（Synthesizer）**：综合证据、处理冲突、评估置信度、给出翻转条件与后续动作。

**关键约束（通过 Prompt 强制）**：

- 数据由后端工具实际取回后**原样**提供给模型，模型只能引用、不能生成数字；
- 接口失败 / 数据为空时，必须输出 `unverifiable`，**严禁静默生成「正常」结论**；
- 不输出确定性涨跌预测、目标价、收益承诺或直接买卖建议。

## 六、数据来源

| 数据源 | 用途 | 接入方式 |
|---|---|---|
| **扶摇金融数据 API** | A 股行情快照、历史 K 线、利润表 / 资产负债表 / 现金流量表、财务指标、标的检索 | REST，请求头 `X-api-key` |
| **同花顺 iFinD MCP** | 公告原文段落（法定披露）、日频金融指标（财报科目/财务比率/估值/单季度）、财经新闻、宏观行业指标 | MCP（Streamable HTTP），请求头 `Authorization` 直接放个人令牌 |
| **豆包大模型** | 命题拆解、证据分类、结论生成、报告撰写、追问 | 火山引擎方舟 OpenAI 兼容接口 |

所有结论均标注**来源、时点、单位、字段与统计口径**，可回溯至原始数据。

## 七、技术架构

```
investment-thesis-verifier/
├── backend/
│   ├── main.py                 # FastAPI：/api/chat(SSE 流式)、/api/conversation/{id}、/api/health
│   ├── config.py               # 环境变量配置
│   ├── data_sources/
│   │   ├── fuyao.py            # 扶摇 API 封装（统一响应结构 + 429 退避重试）
│   │   ├── ifind_mcp.py        # iFinD MCP 客户端（握手/会话复用/限流重试）
│   │   └── ifind_data.py       # iFinD MCP 取数与解析（公告/指标/新闻/宏观）
│   ├── agents/
│   │   ├── llm_client.py       # 大模型调用：稳健 JSON 解析 + 流式输出 + 网络/格式重试
│   │   ├── decomposer.py       # 环节① 命题拆解
│   │   ├── evidence.py         # 环节③④ 分组批量取证与证据分类
│   │   ├── conclusion.py       # 环节⑤ 综合结论
│   │   └── pipeline.py         # 主链路编排：stream_pipeline 事件生成器 + trace 可观测
│   └── prompts/
│       └── templates.py        # 全部 Prompt 模板
├── frontend/
│   ├── index.html              # 简洁对话界面（Tailwind + marked + DOMPurify）
│   ├── app.js                  # SSE 读取、Markdown 流式渲染、会话历史
│   └── styles.css              # 干净的对话与 Markdown 排版
├── tests/                      # 测试脚本与结果（quick_test / test_sse）
├── requirements.txt
├── render.yaml                 # Render 部署蓝图
└── .env.example
```

**技术选型**：FastAPI + 原生异步 httpx + SSE 流式 + 豆包大模型 + Tailwind + marked（Markdown 渲染）。刻意保持轻量、无重型框架依赖，便于审阅与复现。

## 八、本地启动

### 1. 环境要求

- Python 3.10+（云端部署使用 3.12，以使用预编译的 pydantic-core wheel）

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 配置环境变量

复制 `.env.example` 为 `.env`，填入你的 Key：

```bash
cp .env.example .env
```

```ini
FUYAO_API_KEY=你的扶摇Key
ARK_API_KEY=你的方舟Key
ARK_MODEL_MAIN=doubao-seed-2-0-pro-260215
IFIND_MCP_TOKEN=你的iFinD个人令牌（可选）
```

### 4. 启动服务

```bash
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

浏览器打开 <http://127.0.0.1:8000> 即可使用。

> Windows 若同时安装多个 Python，可用 `py -m uvicorn backend.main:app ...` 指定解释器。

## 九、部署到 Render

1. 将本仓库推送到 GitHub；
2. Render → **New +** → **Blueprint**，选择本仓库（会自动读取 `render.yaml`）；
3. 在 **Environment** 中填写 `FUYAO_API_KEY`、`ARK_API_KEY`、`IFIND_MCP_TOKEN`（`IFIND_MCP_URL` 已有默认值，通常无需修改）；
4. 部署完成后获得可公开访问的 Web URL。

## 十、API 说明

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 健康检查与配置状态 |
| POST | `/api/chat` | 统一对话入口（SSE 流式），自动区分「新命题 / 追问」，body：`{"message": "...", "conversation_id": "可选"}` |
| GET | `/api/conversation/{conv_id}` | 历史会话回放，返回最近一次完整验证结果 |

`/api/chat` 以 Server-Sent Events 逐帧推送 `session / meta / status / report_start / answer_delta / followup_done / done / error` 等事件，并带心跳保活；前端据此实时渲染进度与流式 Markdown 报告。

## 十一、测试说明

- `tests/quick_test.py`：端到端主链路（表单版接口）；
- `tests/test_sse.py`：对话版 SSE 三轮测试 —— ① 新命题：进度提示与流式 Markdown 报告；② 同一会话追问、意图识别与逐字流式回答；③ 无关问题识别为 out_of_scope 并引导。

测试覆盖：

- **主链路**：真实命题从拆解到结论的完整流程；
- **流式与会话**：SSE 事件顺序完整、会话 ID 贯通、追问上下文正确；
- **数据缺失 / 接口失败**：扶摇限流（code=429）自动退避重试；取数失败时子问题标记 `unverifiable`，不伪造；
- **大模型异常**：网络 ConnectError / DNS 故障自动重试；模型失败时降级保留原始数据；
- **合规边界**：输出不包含涨跌预测、目标价、买卖建议，事实与推断明确区分。

## 十二、已知边界

1. **iFinD MCP 已接入、但语义检索存在波动**：公告原文与金融指标可稳定支撑核心结论；个别年报附注项（如分产品明细、投资收益合计）在检索未命中时如实标注「无法验证」，不静默伪造。
2. **结论为「验证」而非「预测」**：产品回答「命题是否被现有数据支持」，不对未来走势做确定性判断。
3. **数据口径以扶摇返回为准**：金额为原币元、EPS 为元/股；字段为 `null` 表示未披露，不补零。
4. **单次取数记录上限**：为控制上下文，原始数据默认展示前 8 条记录。
5. Free 部署可能休眠，首次访问需冷启动。
