# 投资命题多证据验证台（Investment Thesis Multi-Evidence Verifier）

> 把一个模糊的「投资命题」自动拆解为可验证子问题，调用真实金融数据形成**支持 / 反对 / 无法验证**的证据链，处理证据冲突，给出**可追溯结论**，并明确「哪些信息变化会翻转当前结论」。

本项目为同花顺 2027 届校招「AI 产品经理（AIME 金融智能 Agent 方向）」测评作品（选题：投资命题与多证据验证）。

---

## 一、它解决什么问题

投资者经常形成需要验证的判断，例如：

- 「贵州茅台 2023 年盈利增长主要来自主营业务」
- 「宁德时代估值回落但基本面没有恶化」
- 「比亚迪近三年盈利能力持续提升」

这些命题往往**模糊、复合、想当然**。人工验证需要：拆问题 → 查报表 → 对数据 → 找反例 → 下结论，耗时且容易只看到支持自己观点的证据（确认偏误）。

本产品把这条研究流程自动化、结构化、可追溯，并**强制同时呈现支持与反对证据**。

---

## 二、目标用户

- **个人投资者 / 投研新手**：需要一套严谨的命题验证框架，避免拍脑袋；
- **专业研究员 / 分析师**：作为研究初稿与证据整理工具，快速形成可追溯的研究底稿；
- **投研团队**：用于研究结论的交叉复核与证伪。

---

## 三、核心链路（产品主流程）

```
输入投资命题
   │
   ▼
① 命题拆解 ── 识别标的、核心主张、时间范围，拆成 3-5 个可验证子问题
   │            （命题模糊时提出澄清问题）
   ▼
② 标的确认 ── 解析为完整 thscode（如 600519.SH），缺失时用检索接口兜底
   │
   ▼
③ 分组取证 ── 按所需数据工具对子问题分组，同一工具只取一次数（含限流退避重试）
   │
   ▼
④ 证据分类 ── 对每个子问题输出 supporting / opposing / unverifiable 证据
   │            （标注证据强度、事实/推断、字段、来源、时点）
   ▼
⑤ 综合结论 ── 总体判断 + 置信度 + 证据冲突 + 关键翻转条件 + 后续研究动作
   │
   ▼
⑥ 继续追问 / 比较 / 保存为研究任务
```

**总体判断取值**：`confirmed`（成立）/ `partially_confirmed`（部分成立）/ `refuted`（不成立）/ `inconclusive`（无法判断）。

## 四、产品功能

| 模块 | 说明 |
|---|---|
| 命题输入 | 文本框 + 一键示例，支持 Ctrl/Cmd+Enter 提交 |
| 命题概览 | 标的、代码、核心主张、时间范围、待澄清问题 |
| 子问题与证据链 | 每个子问题独立卡片，证据按立场用颜色区分，可展开查看**原始数据** |
| 综合结论 | 判断徽标、置信度、结论摘要、证据冲突点、**关键翻转条件**、后续研究动作 |
| 可观测记录 | 可展开查看每个环节的状态与耗时（trace） |
| 继续追问 | 基于已有结论多轮提问，信息不足时提示需要补充的数据 |

## 五、AI 的角色（人机分工）

大模型（豆包 Doubao）在产品中承担**三个分析角色**，但**不直接接触、也不允许编造原始数据**：

1. **拆解分析师（Decomposer）**：把命题结构化、拆成可验证子问题、选择数据工具、给出验证逻辑；
2. **证据分类员（Evidence Classifier）**：基于系统取回的真实数据，组织支持/反对/无法验证证据，区分事实与推断；
3. **研究负责人（Synthesizer）**：综合证据、处理冲突、评估置信度、给出翻转条件与后续动作。

**关键约束（通过 Prompt 强制）**：

- 数据由后端工具实际取回后**原样**提供给模型，模型只能引用、不能生成数字；
- 接口失败 / 数据为空时，必须输出 `unverifiable`，**严禁静默生成「正常」结论**；
- 不输出确定性涨跌预测、目标价、收益承诺或直接买卖建议。

## 六、数据来源

| 数据源 | 用途 | 接入方式 |
|---|---|---|
| **扶摇金融数据 API** | A 股行情快照、历史 K 线、利润表 / 资产负债表 / 现金流量表、财务指标、标的检索 | REST，请求头 `X-api-key` |
| **iFinD MCP** | 公告、研报、新闻等文本类证据 | MCP（当前版本接入中，见「已知边界」） |
| **豆包大模型** | 命题拆解、证据分类、结论生成、追问 | 火山引擎方舟 OpenAI 兼容接口 |

所有结论均标注**来源、时点、单位、字段与统计口径**，可回溯至原始数据。

## 七、技术架构

```
investment-thesis-verifier/
├── backend/
│   ├── main.py                 # FastAPI：/api/analyze、/api/followup、/api/health
│   ├── config.py               # 环境变量配置
│   ├── data_sources/
│   │   └── fuyao.py            # 扶摇 API 封装（统一响应结构 + 429 退避重试）
│   ├── agents/
│   │   ├── llm_client.py       # 大模型调用 + 稳健 JSON 解析 + 网络/格式重试
│   │   ├── decomposer.py       # 环节① 命题拆解
│   │   ├── evidence.py         # 环节③④ 分组批量取证与证据分类
│   │   ├── conclusion.py       # 环节⑤ 综合结论
│   │   └── pipeline.py         # 主链路编排 + trace 可观测
│   └── prompts/
│       └── templates.py        # 全部 Prompt 模板
├── frontend/
│   ├── index.html              # 单页界面（Tailwind CSS）
│   ├── app.js                  # 前端交互与渲染
│   └── styles.css              # 证据配色、徽标、折叠、原始数据块
├── tests/                      # 测试脚本与结果
├── requirements.txt
├── render.yaml                 # Render 部署蓝图
└── .env.example
```

**技术选型**：FastAPI + 原生异步 httpx + 豆包大模型 + Tailwind 单页前端。刻意保持轻量、无重型框架依赖，便于审阅与复现。

## 八、本地启动

### 1. 环境要求

- Python 3.10+（开发与验证使用 3.13）

### 2. 安装依赖

```bash
pip install -r requirements.txt
```

### 3. 配置环境变量

复制 `.env.example` 为 `.env`，填入你的 Key：

```bash
cp .env.example .env
```

```ini
FUYAO_API_KEY=你的扶摇Key
ARK_API_KEY=你的方舟Key
ARK_MODEL_MAIN=doubao-seed-2-0-pro-260215
```

### 4. 启动服务

```bash
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

浏览器打开 <http://127.0.0.1:8000> 即可使用。

> Windows 若同时安装多个 Python，可用 `py -m uvicorn backend.main:app ...` 指定解释器。

---

## 九、部署到 Render

1. 将本仓库推送到 GitHub；
2. Render → **New +** → **Blueprint**，选择本仓库（会自动读取 `render.yaml`）；
3. 在 **Environment** 中填写 `FUYAO_API_KEY`、`ARK_API_KEY`（以及可选 `IFIND_MCP_TOKEN`）；
4. 部署完成后获得可公开访问的 Web URL。

## 十一、测试说明

见 `tests/quick_test.py`（端到端主链路）。测试覆盖：

- **主链路**：真实命题从拆解到结论的完整流程；
- **数据缺失 / 接口失败**：扶摇限流（code=429）自动退避重试；取数失败时子问题标记 `unverifiable`，不伪造；
- **大模型异常**：网络 ConnectError / DNS 故障自动重试；模型失败时降级保留原始数据；
- **合规边界**：输出不包含涨跌预测、目标价、买卖建议，事实与推断明确区分。

---

## 十二、已知边界

1. **iFinD MCP 文本源接入中**：公告 / 研报 / 新闻类证据当前返回「无法验证」，未静默伪造；结构化财务与行情数据链路已完整。
2. **结论为「验证」而非「预测」**：产品回答「命题是否被现有数据支持」，不对未来走势做确定性判断。
3. **数据口径以扶摇返回为准**：金额为原币元、EPS 为元/股；字段为 `null` 表示未披露，不补零。
4. **单次取数记录上限**：为控制上下文，原始数据默认展示前 8 条记录。
5. Free 部署可能休眠，首次访问需冷启动。
